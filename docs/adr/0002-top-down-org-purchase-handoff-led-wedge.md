# Top-down org purchase, handoff-led wedge

The customer is the **organization**: an eng lead buys it and turns it on for the whole team, so all sessions are captured by default — the same way a company owns its GitHub history and Slack. Among the team features, we lead with **handoff/continuity**, not ask-why (the original pain point).

## Considered and rejected

- **Bottoms-up solo wedge** (a free single-player "auto-standup" that seeds adoption, then expands to teams). Rejected because the core value — continuing a teammate's work and asking why about *others'* PRs — is inherently multiplayer; a single-player framing undersells the product.
- **Ask-why as the headline.** Rejected because handoff is the only feature fully unclaimed by competitors, carries zero surveillance baggage, and benefits dev and manager equally — so it both differentiates and defuses the helper-vs-watcher tension. Ask-why is conceptually closer to the crowded oversight space.

## Consequence

GTM is enterprise/top-down, which is slower for a young team — mitigated by a free tier to cultivate internal champions. Re-leading on a different View later would mean repositioning the whole brand, so this is expensive to reverse.
